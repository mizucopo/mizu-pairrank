# 管理画像は保存先から独立した参照で扱う

新規画像の `ImageAsset.path` はASCIIのUUIDファイル名とし、ネイティブの保存先 `PathBuf` とRust側で結合する。Unixの保存先に非UTF-8名が含まれても画像の表示と削除を維持するため、UTF-8へ変換するTauri標準asset protocolに代わり、管理画像だけを返す `pairrank-image` protocolを新規参照に使う。

既存DBの絶対UTF-8パスは書き換えず、従来のasset protocolによる表示と管理ディレクトリ内に限定した削除を維持する。DBの列・スキーマバージョンは変更しない。

画像保存後・DB登録前の終了で残ったファイルは、次に単独で起動した際に回収する。起動時に保存先の排他ロックを取得できた場合のみ、DBの参照をすべて読み取り、参照のない管理UUID画像を削除する。旧絶対パス参照は親ディレクトリの同一性を照合し、別名経由の参照も保持する。参照の照合が完了する前には削除を始めない。管理外ファイル・シンボリックリンクは保持し、DB参照の読み取りに失敗した場合も削除しない。

画像サービスは生存期間中、保存先の共有ロックを保持する。Unixでは起動時に識別した画像ディレクトリ自体をロックし、独立したロックファイルの差し替えによって同じ画像群のロックが分裂することを防ぐ。Windowsでは `.images.lock` を使い、ハンドルを保持する間は削除・名前変更の共有を許可しない。別インスタンスが動作中の場合は回収を延期し、保存からDB登録までの途中にある画像を保護する。キャンセル後も続く画像保存タスクもロックを保持し、プロセス終了時のOSによるロック解放を利用する。旧Unixロックファイルは使用せず、そのまま残す。
