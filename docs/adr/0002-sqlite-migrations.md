# SQLiteと起動時マイグレーション

回答・評価・順位判定窓を同時に保存し、アプリ更新をまたいで再開できるよう、Rust側で管理するSQLiteを採用する。スキーマはPRAGMA user_versionの連番で管理し、アプリのリリース番号および評価モデルのバージョンから独立させる。

初期スキーマはsrc-tauri/migrations/001_initial.sqlに置き、実行ファイルへ組み込む。公開済みSQLは変更せず、次の番号のSQLを追加しdatabase.rsのMIGRATIONSへ登録する。必要な既存データの変換もSQLへ含める。通常操作より前に保存バージョンを確認し、BEGIN IMMEDIATEの取得後に再確認して、未適用分すべてとuser_versionの更新を同一トランザクションで実行する。外部キー整合性を検証してからコミットし、失敗時はスキーマ・データ・バージョンを全体としてロールバックする。

同版は更新不要。新規の空DBは0から初期化する。新しいスキーマのDB、非空の未管理DB、非対応評価モデルは変更せず通常操作を停止し、起動エラーを表示する。自動ダウングレード・初期化による復旧は行わない。マイグレーションSQLはトランザクション内で実行可能な処理に限定し、BEGIN/COMMITやVACUUM、外部ファイル操作を含めない。

起動時の移行完了後も、別のアプリが同じDBを未来版へ移行できるため、通常操作ごとにトランザクション内でuser_versionを確認する。書き込みはBEGIN IMMEDIATEの取得後に確認し、コミットまたはロールバックまでロックを保持して、版確認と更新の間への移行を防ぐ。読み取りは版確認とデータ取得を同じスナップショットで行い、読み取り中に移行がコミットされた場合は次の操作で拒否する。起動後の拒否にも既存のエラー表示を使い、保存版・対応版とアプリ更新の案内を返す。画像参照の読み取りも対象とし、確認に失敗した場合は既存の画像削除中止動作を維持する。

スキーマ変更時は、旧版のデータを持つDBから最新へ移行して内容が保持されるテストを追加する。マイグレーションランナー自体は複数段階の更新、再実行防止、後段失敗時の全体ロールバック、未来版と未管理DBの拒否をテストする。
