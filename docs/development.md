# 開発・技術情報

アプリの紹介と画面は [README](../README.md)、詳しい操作とバックアップは[利用ガイド](user-guide.md)を参照してください。

## 開発環境

- Node.js: [`.node-version`](../.node-version) のバージョンを使用します。
- Rust: [`rust-toolchain.toml`](../rust-toolchain.toml) に従います（stable、rustfmt、Clippy）。
- OSごとのネイティブ開発依存は [Tauri の前提条件](https://v2.tauri.app/start/prerequisites/)を準備します。

フロントエンドは `src/`、Rust のアプリ本体は `src-tauri/` にあります。`dist/` と `src-tauri/target/` は生成物です。

## 起動と品質チェック

```bash
npm ci
npm run tauri dev
```

`npm run dev` 単体ではViteのみが起動するため、保存・比較にはTauriから起動してください。

全品質チェック:

```bash
npm run check
```

TypeScript 7・type-aware Oxlint・Prettier・Vitest・Viteビルドと、Rustのfmt・Clippy・テストを実行します。画像検索のテストはモックを利用し、実APIキーやOSの資格情報ストアにはアクセスしません。

Rust依存の更新時も、テスト専用APIの互換性を含めて `npm run check` で確認し、PRのTauri Quality Checksと全OSのStorage Checksが成功したことを確認してください。特に0.xのminor更新ではAPI変更があり得るため、変更履歴と利用箇所を確認します。SQLトレースを使うテストは、登録・解除とエラー処理を `src-tauri/src/database.rs` の `set_profile_trace` に集約しています。

## 評価と順位判定

「大好き」は相手との好みの差が大きいことを意味します。5段階へ拡張したTrueSkillで評価と不確実性σを更新し、期待情報量の大きいペアを自動選択します。順位は推定評価μの順です。

Tier はリスト内の最高μから最低μまでを5等分して自動で決まり、境界上の値は下位の Tier に入ります。同じμの項目は同じ Tier に入り、全項目が同点なら C に入ります。比較で評価が変わると Tier も更新されます。

終了条件は、全項目のσが2.5以下、かつ直近max(20,項目数)回答の間に各項目の順位幅が1位以内になることです。新しい項目の追加・削除・比較再開で終了判定の履歴窓をリセットし、既存の評価は保持します。項目数に固定上限はありません。通常500項目未満を想定しています。

モデルのパラメーター・ペア選択・取り消しの実装は[評価と比較](rating.md)を参照してください。

## リスト共有のファイル形式

リストのエクスポートは `*.pairrank.zip` として保存し、ZIP内に `list.json` を1つ格納します。リスト名・登録順の項目・タグを含み、画像は明示的に選択した場合だけ含みます。比較履歴・評価・順位・内部ID・画像の保存パスや取得元URL・検索用APIキーは含みません。

JSONの形式名は `mizu-pairrank-list`、バージョンは `1` です。ZIP・展開後のJSONとも50MiB・5,000項目・1,000タグ・タグ割り当て合計50,000件まで、リスト名と項目名は1,000文字・タグ名は30文字まで対応します。任意の画像は1枚20MiB以下のBase64 PNGです。画像は通常の登録と同じサイズ・画素数制限で再保存し、埋め込まれたメタデータを引き継ぎません。未知のフィールド・バージョンや不正なタグ参照は取り込みません。ZIPは非暗号化・分割なし・ZIP64なし・コメントなしの形式に対応し、他のファイルや不正なパスは取り込みません。

画像を含める場合は500枚・合計1億画素までです。利用者向けの操作と再配布時の注意は[リストの共有](user-guide.md#リストの共有)を参照してください。

## 保存とスキーマ更新

DBのスキーマバージョンを保持し、起動時に必要なマイグレーションを順番に自動適用します。変更はまとめて確定し、失敗した場合は更新前のスキーマ・データ・バージョンを維持します。新しいDBを古いアプリで開いた場合は、アプリの更新を案内して操作を停止します。

保存先・バックアップ手順は[利用ガイド](user-guide.md#保存とアップデート)、スキーマ変更の手順と保証範囲は[保存・移行・画像管理](storage.md)を参照してください。
